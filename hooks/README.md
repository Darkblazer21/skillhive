# hooks/

Three companion, single-purpose hooks - split because Git only exposes
the commit-message file path to the `commit-msg` event, never to
`pre-commit`, and because two independent checks now both react to the
`pre-commit` event.

| File | Git hook event | Checks |
|---|---|---|
| `pre-commit-review.sh` | `pre-commit` | Hardcoded secrets in the staged diff (OWASP A07) |
| `prose-pattern-lint.sh` | `pre-commit` | AI writing tics in staged deliverable text (see `prose-conventions` skill) |
| `commit-msg-review.sh` | `commit-msg` | Conventional Commits format |

## Install

```bash
bash hooks/install.sh
```

Git only allows a single file named `.git/hooks/pre-commit` - since two
checks above both react to that event, `install.sh` does **not** copy
either one directly over `.git/hooks/pre-commit` (the second copy would
silently replace the first, and only one check would ever run). Instead
it writes `.git/hooks/pre-commit` as a small dispatcher that calls
`hooks/pre-commit-review.sh` and `hooks/prose-pattern-lint.sh` in
sequence, stopping at the first one that blocks. `commit-msg-review.sh`
is the only check on its event today, so it's copied directly to
`.git/hooks/commit-msg`.

Adding a fourth `pre-commit`-type check later: drop the script in this
folder and add its filename to the `PRE_COMMIT_CHECKS` list at the top
of `install.sh` - never copy it directly to `.git/hooks/pre-commit`.

`hooks/*.sh` themselves are ordinary files versioned with the repo;
`.git/hooks/*` is not versioned by git and must be regenerated by
running `bash hooks/install.sh` again after every fresh clone.
